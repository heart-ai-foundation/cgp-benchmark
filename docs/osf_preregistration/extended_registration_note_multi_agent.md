# Extended Registration Note: Multi-Agent Companion Benchmark

This note records a planned companion extension to the public OSF registration for the Continuity Governance Prompting Drift Reduction Benchmark. The primary preregistered benchmark remains unchanged: it evaluates baseline prompting against Continuity-Governed Prompting on the originally registered task set, run plan, and outcome measures. The extension described here is intended to evaluate whether the same governance effect generalizes across additional agent platforms. It should be treated as an amended or companion analysis rather than silently pooled into the primary confirmatory analysis.

The extension keeps the core experimental logic fixed. Each agent platform receives the same benchmark tasks under two prompt conditions, baseline and Continuity-Governed Prompting. The baseline condition provides the task description, relevant files, and verification commands. The Continuity-Governed Prompting condition adds the run-specific protocol scaffold, manifest, lock file, allowed-file boundary, non-goals, stop condition, and evidence-trio requirement. The central comparison remains whether the governed prompt reduces prompt drift, improves stop-condition behavior, and improves auditability while preserving task success.

The additional agent platforms planned for the extension are Codex and Gemini CLI. These platforms are added through a separate deterministic extension run plan stored at `runs/agent_extension_run_plan.csv`, with metadata stored at `runs/agent_extension_run_plan_metadata.json`. The extension plan uses the same seed, task definitions, conditions, and replication count as the primary plan, but its rows are recorded separately so that primary and extension analyses remain distinguishable. Claude Code data collected under the primary plan should remain the primary preregistered dataset. Codex and Gemini CLI data should be analyzed as external-validity evidence unless a formal OSF amendment explicitly designates them as part of an expanded confirmatory analysis.

The extension uses the same raw-data structure as the primary benchmark. Each run receives an isolated git worktree, a generated prompt, run metadata, captured transcript, git diff, metrics file, verification record, and, for Continuity-Governed Prompting runs, the required evidence trio consisting of a design note, an operational run record, and a machine-readable evidence JSON file. Runs are captured under `runs/raw/RUN_ID/`. Invalid or harness-defect runs are preserved under `runs/raw/invalid/` and are not reinterpreted as valid benchmark observations.

The extension preserves the same primary measurement concepts. Scope drift is measured by comparing changed files against the task-specific allowed-file set, with CGP evidence files treated as allowed operational evidence for CGP runs. Task success is measured by the preregistered verification commands associated with each task. Scaffold adherence is measured by evidence-trio completeness for CGP runs. Stop-condition behavior is evaluated from the agent transcript and the run validity record. The analysis should report results separately by agent platform and should avoid aggregating across platforms without explicitly modeling platform as a factor.

This extension is motivated by external validity and practical deployment relevance. If the observed CGP effect appears across multiple coding-agent systems, the evidence becomes stronger for the claim that continuity governance is a portable control pattern rather than an artifact of one agent implementation. If effects differ by platform, those differences are also informative because they identify where governance scaffolds transfer cleanly and where tool-specific adaptation is required.

The extension should begin only after the extension plan and runner scripts are committed to the repository. The relevant runner scripts are `scripts/run_gemini_cli.py` for Gemini CLI and `scripts/run_codex_exec.py` for Codex. The extension should be documented in the final paper as a companion or amended analysis with exact dates, commits, agent versions where available, and any deviations from the primary preregistration.
